# GRANBRIDGE v0.1.4 — UI Polish & Graphics (design spec)

- **Date:** 2026-05-25
- **Status:** Draft for review
- **Branch / worktree:** `feat/ui-polish-v0.1.4` in an isolated worktree (a sibling agent holds the shared checkout on `feat/server-port-443-only`; integrate via PR, never local-merge).
- **Theme:** comprehensive UI/graphics polish, shipped as one release.

## 1. Goal

Make GRANBRIDGE *feel* premium — the most polished remote-darts desktop app — without adding dependencies or touching the BLE/protocol/game-engine layers. Every change is **additive** (extend/wrap existing components, add props) rather than a rewrite, and **dependency-light** (hand-rolled SVG/CSS/Web-Audio, no WebGL or animation libraries).

## 2. Locked decisions (from the brainstorm)

- **Dartboard → genuine 3D in pure CSS/SVG.** Stylish base: metallic wire, lit/bevelled segments, raised number ring, board thickness, contact shadow, dart-landing marker. **~17° "mounted-on-wall" tilt during play**; a **cinematic ~26° + glow angle is reserved for checkout/win moments** (same renderer, different props).
- **Multiplayer game screen → "Broadcast rail" layout**, fitting opponent video + your video + board + score in **one viewport (no scrolling)** on the 1280×800 window.
- **Fullscreen toggle** in the header.
- **Verification:** the *feel* (animation/3D/sound) is confirmed in the **running app**, not in unit tests. Tests cover behavior/props/structure; they do not assert visual feel.

## 3. Current baseline (what already exists)

- Views (`ui/src/views/`): `LiveGame`, `Setup`, `History`, `Profile`, `Leaderboard`, `Multiplayer`. Tab nav in `App.tsx`.
- Boards (`ui/src/components/boards/`): `X01`, `Cricket`, `Atc`, `FreePlay`, `CountUp`, `Medley`.
- `Dartboard.tsx`: accurate **flat** SVG board (segments, bulls, `highlight` + `heatmap` props). Hit = amber fill + `dartboard-hit` brightness pulse.
- Sound (`ui/src/sound/`): `SynthPack` (procedural Web-Audio synth) + `SoundManager` + `decide`/`manifest`. Cues: hit, hit-treble, hit-bull, miss, bust, leg-won, game-won, one-eighty, checkout-available.
- Celebration (`Celebration.tsx`, canvas confetti on `leg_won`) + `CheckoutOverlay.tsx` (video-first with procedural fallback for `game-won`/`leg-won`; respects `reducedMotion`).
- Theme: "arcade dark" CSS variables + keyframes (`dartboard-hit-pulse`, `score-pop`, `bust-shake`) in `index.css`. Tailwind. No graphics/animation/sound libraries.

## 4. Architecture

- **Motion:** add CSS keyframes/utility classes in `index.css` and a tiny `useReducedMotion` helper. Do **not** build a motion framework — extract shared bits only when a second consumer appears.
- **Dartboard:** extend the existing component with new optional props (`tilt?: "flat" | "play" | "hero"`, `dart?: {bed}` marker, style refinements). A CSS `perspective` wrapper applies the tilt. Existing `highlight`/`heatmap` behavior preserved (History reuses it flat).
- **Sound:** extend `SynthPack`/`decide` with any new cues; reuse the existing fire-and-forget play path.
- **Multiplayer layout:** a new presentational shell component (e.g. `MpGameLayout`) that arranges existing pieces (`VideoTile`, `LiveGame`, controls, `OpponentCard`) into the rail with viewport-height sizing. Game logic and `mpSession` untouched.
- **Fullscreen:** a `useFullscreen` hook — Tauri window API (`@tauri-apps/api/window` `setFullscreen`) when running under Tauri, browser Fullscreen API fallback — wired to a header `FullscreenToggle` button alongside `SoundToggle`/`VideoToggle`.

## 5. Slices (build units; each becomes a section of the implementation plan)

### Slice 1 — 3D dartboard + gameplay feel
- `Dartboard.tsx`: stylish base (metallic wire via gradient, lit/bevelled segments, raised number ring, board thickness, contact shadow); `tilt` prop with CSS perspective; **dart-landing marker** for the last dart (not just bed highlight); refined hit pulse. Keep flat mode for History/heatmap.
- `LiveGame.tsx`: pass the play tilt; surface the dart marker from `lastHit`.
- Scoreboard dynamism across the 6 boards (shared patterns): animate score change (count/roll on `X01`, mark pop on `Cricket`), bust-shake on the active card, clearer active-player emphasis, per-visit display where the data exists, checkout-path styling.
- Tests: board renders with new props; dartboard renders the marker/tilt class; existing tests stay green.

### Slice 2 — Big moments (checkout & win)
- On `game_won`/`leg_won` (and checkout-available), swing the dartboard to the **cinematic hero angle** briefly; coordinate with `CheckoutOverlay`/`Celebration`.
- Enrich the win/checkout sequence (staged text + glow + confetti already exist — tighten timing and tie in the board swing); ensure procedural fallback + `reducedMotion` paths still work.
- Wire `SynthPack` cues to the moments if not already (`one-eighty`, `checkout-available`, `leg-won`, `game-won`).
- Tests: overlay/celebration still fire on trigger; reduced-motion still short-circuits.

### Slice 3 — Screen polish & cohesion
- Apply consistent theme tokens, spacing, and headings across `Setup`, `Profile`, `Leaderboard`, `History`; add tasteful screen-transition + empty-state treatments; polish the header/nav.
- No behavior change — visual cohesion only.
- Tests: screens still render their key content; no regressions.

### Slice 4 — Multiplayer broadcast layout + Fullscreen
- `MpGameLayout` shell: board+score main area; right rail = opponent video (large), your video (small), `OpponentCard`, controls; viewport-height, **no scroll**. Used by `Multiplayer.tsx` when a remote game is in progress; pre-game keeps the join/lobby panel.
- `useFullscreen` hook + `FullscreenToggle` in the header (Tauri window API + browser fallback; hidden/no-op where unsupported).
- Tests: layout renders the regions with the expected pieces; fullscreen hook guarded for non-Tauri/jsdom; toggle reflects state.

## 6. Cross-cutting

- **Accessibility:** honor `prefers-reduced-motion` (and the existing video `reducedMotion` setting) everywhere new motion is added; preserve ARIA labels/roles.
- **Performance:** SVG/CSS only; the dartboard re-renders on every throw, so the 3D treatment must stay cheap (no per-frame JS, no filters that thrash).
- **No new dependencies.**
- **Out of scope / deferred:** WebGL/Three.js board; BLE/protocol/engine changes; the server single-port-443 work (separate, sibling-owned); CORS tightening from bug #3 (optional follow-up before release).

## 7. Build & integration

- Isolated worktree `feat/ui-polish-v0.1.4`; **TDD per slice**; **green-gate before any merge**: `npm --prefix ui test` + `npm --prefix ui run build` + `python -m pytest server -q` + `python -m pytest -q`.
- Likely **subagent-driven** per slice (sonnet; read task-from-file), given the breadth.
- Integrate to `main` via PR(s); never local-merge while the sibling holds the shared checkout.
- **v0.1.4 release** then bundles these slices + the already-merged fixes (sidecar cleanup, broker default, bug #3 history fix) per `docs/RELEASING.md` (full release, signed, updater chain verified).

## 8. Risks

- Scope is large (four passes + fullscreen). Mitigation: independent slices, each shippable; if time runs short, the release cut can drop a not-fully-polished slice rather than ship it half-done.
- Visual "feel" can only be judged live — expect a round of in-app tweaks after the first build.
- Multiplayer layout interacts with real WebRTC video sizing — verify with the running app / a real 2-peer session, not just jsdom.
